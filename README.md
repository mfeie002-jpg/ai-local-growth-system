# itsfeierabend.ch

Standalone Swiss platform for digital business diagnostics. The product is being positioned around AI Business Audits, website and SEO analysis, AI-search visibility, lead and conversion diagnostics, CRM workflows and automation.

This repository is **not** the Feierabend Services or Umzugscheck codebase. Their offers, campaigns, leads, tracking containers and production data must not be reused here.

## Current status

- Working branch: `feat/itsfeierabend-final-launch`
- Public domain: `https://itsfeierabend.ch`
- Frontend: React 18, TypeScript 5, Vite 5, React Router, Tailwind CSS and shadcn/Radix components
- Backend: Supabase database and Edge Functions
- Build output: Vite bundle plus route-specific static HTML entry points generated by `scripts/generate-static-entrypoints.mjs`
- Test surface: TypeScript, ESLint, production build and Playwright E2E

The legal entity, postal address, responsible person and final production processor inventory are not yet verified. They are launch blockers documented in the imprint and privacy-policy source; do not replace them with guessed data.

## Local setup

Use a current Node.js LTS release and npm.

```sh
git clone <repository-url>
cd itsfeierabend
git switch feat/itsfeierabend-final-launch
npm ci
npm run dev
```

The Vite development server is configured for port `8080`.

## Frontend environment

Create a local environment file that is excluded from Git. The frontend currently references:

```text
VITE_SUPABASE_URL
VITE_SUPABASE_PUBLISHABLE_KEY
VITE_SUPABASE_PROJECT_ID
VITE_TURNSTILE_SITE_KEY
VITE_GA4_MEASUREMENT_ID
```

Only browser-safe publishable values may use the `VITE_` prefix. Service-role keys, API keys, webhook secrets and provider credentials belong in the Supabase/deployment secret store, never in frontend variables or committed files.

The Edge Functions reference optional provider secrets for database access, audit enrichment, email, anti-abuse, voice and notification services. A reference in code does **not** prove that a provider is active in production. Verify the deployed configuration and update the privacy inventory before launch.

## Development commands

```sh
npm run dev        # Vite development server
npm run typecheck  # TypeScript without emitting files
npm run lint       # ESLint
npm run build      # production bundle + static route entry points
npm run preview    # preview the built site
npm run test:e2e   # Playwright tests
```

Run `npm run build` before the default E2E command. The current Playwright configuration starts the preview with `bunx`; if Bun is unavailable, start `npm run preview -- --port 4173 --strictPort` separately and set `PLAYWRIGHT_BASE_URL=http://localhost:4173`.

## Expected change workflow

1. Confirm `git status --short` before editing; the launch branch can contain parallel work.
2. Keep changes scoped and preserve unrelated modifications.
3. Run typecheck, lint and the production build.
4. Run relevant E2E tests against the built preview.
5. Inspect the final diff for secrets, placeholder claims, unapproved prices and cross-project content.
6. Commit intentionally on `feat/itsfeierabend-final-launch`.
7. Prepare a reviewable pull request with test evidence and remaining blockers.

Do not merge a protected production branch or publish production without an approved rollback path.

## Product and content rules

- Position itsfeierabend.ch as a diagnostic and growth-intelligence platform, not a generic “AI-first marketing agency”.
- Keep automatically measured signals, user inputs, estimates and expert review visibly separate.
- Do not promise Google, ChatGPT or AI-answer rankings.
- Do not publish customer logos, testimonials, certifications, performance numbers or partnerships without verification and permission.
- Do not publish fixed prices unless they have been explicitly approved for this project.
- Semrush volume, KD, CPC and domain metrics are currently unavailable because the connected account did not expose reports after returning insufficient API units. Use the dated evidence files in `docs/` and never fill missing values from memory.
- Treat existing connected projects as case context only when the relationship and claims are verified.

## Security and data boundaries

- itsfeierabend leads must use its own database records, attribution and consent state.
- Never copy production leads, tracking IDs, service-role credentials or campaign data from Feierabend Services or Umzugscheck.
- Validate Row Level Security, grants, rate limits, anti-abuse checks and error redaction before production.
- Do not put personal data or secrets into analytics events, URLs, logs, screenshots or test fixtures.
- Use synthetic test leads and clearly remove or label them after QA.
- DNS changes, destructive production migrations, paid subscriptions, ad publication and messages to real contacts require explicit approval.
